## 1. 粒度（1行＝何か）

⚠️ **1行＝ 金融機関 × 商品 × 金利タイプ**（案）。

例: 鹿児島銀行（2026/10/1 公式）
| id | 商品 | 金利タイプ | 基準金利 | 最優遇 | 最低優遇 |
|---|---|---|---|---|---|
| kagin_pro_v | かぎん住宅ローン（プロパー） | 新変動 | 3.625 | 1.850 | 2.350 |
| kagin_pro_f2 | 〃 | 固定2年 | 3.950 | 2.350 | 2.850 |
| kagin_pro_f3 | 〃 | 固定3年 | 4.450 | 2.500 | 3.000 |
| kagin_pro_f5 | 〃 | 固定5年 | 4.800 | 2.800 | 3.300 |
| kagin_pro_f10 | 〃 | 固定10年 | 5.250 | 3.350 | 3.850 |

- ⚠️ 同じ商品の金利タイプは `product_group`（例 `kagin_pro`）でまとめる → 計画書で「この商品の固定5年」に切り替えられる。
- ⚠️ 既存の id（`kagin` など）は残す（過去の計画書の照合キー）。新しい粒度の行は新しい id。

## 2. 表の変更（案）

### loan_product（列を足す）
| 列 | 内容 |
|---|---|
| `bank_id` | 金融機関の鍵（例 `kagin`）。⚠️ 金融機関単位の集計・URL 一覧に使う |
| `product_group` | 同じ商品の金利タイプをまとめる鍵（例 `kagin_pro`） |
| `kind` | `v`（変動）／ `f`（固定期間選択）／ `full`（全期間固定） |
| `fixed_years` | 固定期間（年）。変動は 0、全期間固定は返済期間 |
| `plan` | 商品系統（プロパー／保証会社型／プレミアム／フラット35 など） |
| `target` | 新規・借換・両方 |
| `max_years` / `max_amount` | 借入期間の上限（年）／借入額の上限（円） |
| `rate_url` | ⚠️ **金利が載っているページ**（スクレイピング先）。`url`（公式トップ）とは別 |

### loan_rate（列を足す）
| 列 | 内容 |
|---|---|
| `base_rate` | 店頭基準金利 |
| `rate` | ⚠️ 最優遇（従来どおり。LOANS の rate） |
| `rate_max` | 最低優遇（優遇が最も少ないとき）。⚠️ 計画書で「幅」を出す |
| `after_cut` | 固定期間終了後の引下げ幅（基準金利から）。⚠️ 公表されていなければ空 |
| `hoshoMode` | `lump`（一括・円）／ `rate`（金利上乗せ %） |
| `conditions` | 引下げ条件（給与振込・カード・住宅性能 など） |
| `dan_options` | 団信の選択肢と上乗せ金利（下の書式） |
| `evidence` | ⚠️ **ページ上の該当箇所の原文**（例「新変動金利型 基準金利3.625% 新規実行金利1.850%～2.350%」）。⚠️ 確認・監査用 |
| `fetched_at` | Claude Desktop がページを読んだ日時 |
| `status` | `ok`（全部取れた）／ `partial`（一部不明）／ `not_found`（ページに無い・読めない） |

### 団信の書式（`dan_options`、1列に入れる案）
```
一般団信:0|がん100%:0|三大疾病(地銀協):0.3|三大疾病(カーディフ):0.1|全疾病:0.2
```
- `名前:上乗せ金利(%)` を `|` で区切る。⚠️ 無料は 0。⚠️ 分からなければ空。
- ② が分解して検査（名前が空・上乗せが数字でない → その行は誤り）。

## 3. CSV v2（Claude Desktop が返す形）

列（案）:
```
id,bank_id,product_group,g,fi,pn,plan,kind,fixed_years,target,
base_rate,rate,rate_max,after_cut,asof,
fee,feeMode,feeVal,hosho,hoshoMode,hoshoVal,
dan_options,conditions,max_years,max_amount,
url,rate_url,source,evidence,fetched_at,status,note,warn
```
- ⚠️ **推測で埋めない**。分からない値は空欄、`status=partial`、`warn` に理由。
- ⚠️ 数値列は数字だけ（% 円 カンマなし）。
- ⚠️ `evidence` は必須（`status=not_found` を除く）。

### 登録時の検査（② ・ドライラン → 確認 → 確定。SatBase 物件更新と同じ流れ）
- 形式: id 形式、kind と fixed_years の整合、0 ≤ 金利 ≤ 20、`rate ≤ rate_max ≤ base_rate`、dan_options の書式
- ⚠️ 前回確定値との比較: ±0.5% 以上動いた金利は**黄色で警告**（読み間違いの見張り）
- ⚠️ `evidence` に `rate` の数字が含まれていない行は警告
- ⚠️ 1行でも誤りがあれば何も書かない（従来どおり）。警告は確認のうえ登録できる
- 既存の CSV v1（17列）も引き続き受け付ける（見出しで判別）

## 4. Claude Desktop での作業の流れ

1. Dashboard「ローン情報更新」→ ⚠️ **調査依頼セットを書き出す**（現在の CSV ＋ `rate_url` 一覧 ＋ 依頼文）
2. Claude Desktop に貼る → 各 `rate_url` を読んで CSV v2 を返してもらう
3. Dashboard にアップロード → 差分・警告を確認 → 確定
- ⚠️ 金融機関ごとにページの作りが違う（例: 南日本銀行の一覧ページは金利が一部しか無い → 商品ごとの詳細ページを `rate_url` に登録する）
- ⚠️ 読み取りの誤り（数字の取り違え）は `evidence` と前回比の警告で拾う

## 5. このセッションでの分析

- ⚠️ 分析には確定済みの金利が要る。① 本番 DB の値を手元に持ってくる方法が必要:
  - 案A: Dashboard に「確定済み金利の CSV 書き出し」（履歴込み）→ ファイルを渡してもらう
  - 案B: Claude Desktop が返した CSV をそのまま渡してもらう（確定前の値）
- できる分析の例:
  - 借入額・期間・団信を固定したときの、商品×金利タイプ別の総支払額（最優遇／最低優遇の幅）
  - 手数料型と保証料型の損益分岐（借入額・期間による）
  - 固定期間選択型の「期間終了後の金利」の想定別の比較
  - 月次の推移（基準日ごとの積み上げ）、金融機関の順位の変化
  - 計画書で提案した商品の傾向（funding_plan.loans）

## 6. funding-plan/index.html の細かな設定（案）

| 設定 | 内容 |
|---|---|
| 金利の出所 | ⚠️ 起動時に ② の最新金利（v2）を読む。読めなければ HTML 内の値（従来どおり）。ファイル読込は残す |
| 金利タイプ | 商品カードで 変動／固定2・3・5・10年／全期間 を切り替え（同じ product_group） |
| 優遇 | 最優遇／最低優遇／手入力 |
| 団信 | `dan_options` から選ぶ → 上乗せ後の金利で試算 |
| 固定期間終了後 | 想定金利: 今の変動金利／基準金利−after_cut／手入力 |
| 金利上昇シナリオ | 変動に「n年後に+x%」などの段階（比較表に並べる） |
| 手数料型／保証料型 | 両方ある商品は選べる |

- ⚠️ 計算は元利均等で、⚠️ 金利が変わる時点で残高から返済額を計算し直す（2段・多段）。
- ⚠️ 計画書には**保存時の金利と設定**を顧客ごとに残す（従来どおり。後から金利が変わっても過去の計画書は動かない）。
