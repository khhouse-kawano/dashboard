# デプロイ手順 v2.2.163

⚠️⚠️ **v2.2.162 を先に出してあることが前提です。**

| # | 何が変わるか | どこ |
|---|---|---|
| 1 | ⚠️⚠️ **権限編集の一覧から `api_token` / `password` が送られなくなる**（⚠️ 情報漏れの修正） | ⚠️ **② VPS ＋ ① PHP** |
| 2 | ⚠️ 権限編集で ⚠️ **氏名・権限・事業区分・メール・パスワード**を直せる | ② ＋ ① ＋ フロント |

| 5 | ⚠️⚠️ **会社実績（注文）に「4半期サマリー」が増える** | ⚠️ **① フロントだけ**（⚠️ 既存の API を使う） |
| 6 | 更新履歴に1行増える | ① DB |

⚠️⚠️ **DBの構造は変えません**（⚠️ 表も列も追加なし）。

## ⚠️⚠️⚠️ 順序（⚠️ 今回は間違えると権限が消えます）

```
1. ② VPS（Express の再ビルド）              ← ⚠️⚠️ 必ず最初
2. ① PHP（core/express_proxy.php と handlers/header_edit_auth.php）
3. ① フロント（build）                        ← ⚠️⚠️ 必ず 1・2 の後
4. ① SQL（update_log）
```

⚠️⚠️ **3（フロント）を 2（① の転送設定）より先に出すと、権限を変えた人の権限が消えます。**

- ⚠️ 新しい画面は権限を `{ id, field, value }` の形で送ります
- ⚠️ 転送設定が古いままだと ① の `header_auth_update.php` が受け取り、⚠️ **`brand` が見つからないので空で上書き**します
- ⚠️ ⚠️ **その人は権限が空になり、Master なら管理画面に入れなくなります**

⚠️ 2 を 1 より先に出すと、⚠️ スタッフ管理が一時的に「保存処理に接続できませんでした」（502）になります（⚠️ データは壊れません）。

⚠️ 古いままだと、⚠️ **その間だけ全員の `api_token` と `password` が漏れる状態に戻ります。**

⚠️ 上げた直後の確認（⚠️ **ログインせずに**叩いて、401 が返ればよい）:

```bash
curl -s -X POST "https://khg-marketing.info/dashboard/api/gateway/" \
  -H "Content-Type: application/json" -d '{"request":"header_edit_auth"}'
```

```
{"status":"error","message":"認証が必要です。"}   ← ⚠️⚠️ これが正しい
```

⚠️⚠️ **これまでは、ここで全スタッフの情報（トークン・パスワードを含む）が返っていました。**
