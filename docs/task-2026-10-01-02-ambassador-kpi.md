
⚠️⚠️ **`master_data_id` という名前だが、建売・中古の id も入る**（⚠️ 同期処理を参照）。

⚠️ ⚠️ **台帳は1セル保存のたびに一覧を引き直す画面**であり、

⚠️ 顧客1件につき1行を返すだけ。⚠️ **歩留まりの判定は画面側。**

| 2 | ⚠️⚠️ **モーダルの一覧に結局その行が要る。** ⚠️ 数だけ返すと**2回取りに行くことになる** |

## ⚠️ 歩留まりの判定（⚠️ **shopTrend と同一**）

⚠️ 移植元: `components/shopTrend/ShopTrendOrder.tsx` の `getValue()`。

| KPI | 判定 | 分母 |
|---|---|---|
| **総反響** | ⚠️⚠️ **その人からの反響すべて**（⚠️ **未同期を含む**） | — |
| **初回面談** | ⚠️ 来場日がある **または** ⚠️⚠️ **その先へ進んでいる** | 総反響 |
| **次アポ** | ⚠️ 第二面談・事前審査・契約の ⚠️ **いずれかがある** | 初回面談 |
| **契約** | ⚠️ 契約日があり、かつ ⚠️⚠️ **`status` が `契約済み` か `解約`** | 初回面談 |

### ⚠️⚠️ 「来場日が無くても先へ進んでいれば初回面談に数える」

⚠️ shopTrend の ⚠️ **「期間」側の分岐**と同じ扱い（⚠️ 月指定側ではない）。
⚠️ ⚠️ **入れないと、来場日の入力漏れで「次アポ ＞ 初回面談」というありえない歩留まりが出る。**

⚠️ ⚠️ **実データで実際に起きる**（⚠️ 検証7を参照。⚠️ 建売・中古の契約済み2件は来場日が空だった）。

### ⚠️ 期間で絞らない

⚠️⚠️ **全期間の通算。** ⚠️ 台帳は「誰がどれだけ貢献しているか」を見る画面であり、
⚠️ 月ごとの推移を見る画面ではないため。

## ⚠️ 追加した関数

### ⚠️ `frontend/src/components/header/ambassadorKpi.ts`（新規）

| 関数 | |
|---|---|
| `has(value)` | ⚠️ 日付が入っているか（⚠️ 空白だけも「無し」） |
| ⚠️ **`movedOn(c)`** | ⚠️⚠️ **次アポ**（第二面談・事前審査・契約のいずれか） |
| ⚠️ **`isContract(c)`** | ⚠️⚠️ **契約**（⚠️ 日付＋`status`） |
| ⚠️ **`isInterview(c)`** | ⚠️⚠️ **初回面談**（⚠️ 来場日 または `movedOn`） |
| ⚠️ **`buildStages(total, customers)`** | ⚠️ 4段を組み立てる |
| ⚠️ **`rate(count, denominator)`** | ⚠️⚠️ **分母0なら `null`**（⚠️ `0%` と出さない） |

```ts
/**
 * 次アポ（＝初回面談のあとに進んだ人）。
 *
 * ⚠️⚠️ **第二面談・事前審査・契約のいずれかがあれば「進んだ」とみなす。**
 *   ⚠️ 移植元と同じ。⚠️ ⚠️ **第二面談の日付を入れずに契約まで進む案件があり、**
 *     ⚠️ 第二面談だけを見ると**契約者が次アポから漏れて歩留まりが逆転する。**
 */
const movedOn = (c: KpiCustomer): boolean =>
    has(c.appointment) || has(c.screening) || has(c.contract);

/**
 * 契約。
 *
 * ⚠️⚠️ **日付だけでなく `status` も見る。**
 *   ⚠️ 契約日が入ったまま失注・保留になっている行があり、
 *     ⚠️ ⚠️ **日付だけで数えると契約数が実際より多く出る。**
 */
const CONTRACT_STATUS = ['契約済み', '解約'];

const isContract = (c: KpiCustomer): boolean =>
    has(c.contract) && CONTRACT_STATUS.includes((c.status ?? '').trim());

/**
 * 初回面談。
 *
 * ⚠️⚠️ **来場日が未入力でも、その先へ進んでいれば数える。**
 */
const isInterview = (c: KpiCustomer): boolean => has(c.interview) || movedOn(c);

/**
 * 歩留まり（%）。
 *
 * ⚠️⚠️ **分母が0のときは null を返す。** `0%` と出さないこと。
 *   ⚠️ ⚠️ **「まだ誰も来ていない」と「来たが誰も進まなかった」は意味が違う。**
 */
export const rate = (count: number, denominator: number | null): number | null => {
    if (denominator === null || denominator === 0) return null;
    return Math.floor((count / denominator) * 100);
};
```

## ⚠️⚠️ 2026-10-01 追記：歩留まりが画面に出ていなかった

### ⚠️ 症状

⚠️ 台帳は表示されるのに、⚠️⚠️ **歩留まりの数字だけが出ない。**

### ⚠️⚠️ 原因：① の転送許可リストへの入れ忘れ

⚠️ ⚠️ **画面は ① に投げる。** ⚠️ `ambassador_kpi` を
`backend/src/core/express_proxy.php` に書いていなかったため、
⚠️⚠️ **① が `handlers/ambassador_kpi.php` を探して 404 を返していた。**

```
POST http://localhost:8080/  {"request":"ambassador_kpi"}
  → 404 {"status":"error","message":"該当する処理がありません。"}
```

⚠️ ⚠️ **②単体（:3001）では最初から動いていた**ので、
⚠️⚠️ **API単体の検証だけでは見つけられなかった。**
⚠️ ⚠️ **画面と同じ経路（① 経由）で確かめるべきだった。**

⚠️ 画面は ⚠️ **KPIの失敗で止まらない作り**にしてあるため、
⚠️⚠️ **台帳は普通に表示され、数字だけが黙って出ない**という症状になった。

### ⚠️ 直したもの

| 入れた先 | 理由 |
|---|---|
| `expressProxyRequests()` | ⚠️ ② へ転送する |
| ⚠️⚠️ **`expressProxyExclusive()`** | ⚠️ ⚠️ **① に PHP ハンドラが無い。** ⚠️ 入れないと落ちたとき404になる |

⚠️⚠️ **②専用の request を足したら、必ず両方に書くこと。**
