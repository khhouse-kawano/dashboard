## 順序

```
1. ② Express（build）                      ← フェスタ
2. LP（index.html）                         ← フェスタ。⚠️ 1 のあと
3. ① SQL（fill_sheet_shop：空の shop を埋める） ← 日報。⚠️ 5 より前
4. ① フロント（build）                      ← ⚠️⚠️ 5 より前
5. ① PHP（daily_report.php）               ← ⚠️⚠️ 4 のあと
6. ① SQL（update_log）
```

⚠️⚠️ **4 → 5 の順を守ること。**
- ⚠️ 新しい PHP は ⚠️ **事業と月の指定が無いと 400** を返す。⚠️ 古いフロントは指定しないので、⚠️ **5 を先に出すと日報が真っ白になる。**
- ⚠️ 新しいフロント ＋ 古い PHP は動く（⚠️ 古い PHP は指定を無視して全件を返すだけ。⚠️ 重いのは今と同じ）。

⚠️ 3 を 5 より後にすると、⚠️ その間 ⚠️ **shop が空だった行（主にかえる）の行動量が日報から消える**（⚠️ 3 を流せば戻る）。

⚠️ 2 を先に出しても予約は壊れません（⚠️ `m` が無視されて NULL になるだけ）。⚠️ ただしその間の長原木・junko の予約は ⚠️ **媒体が残らない**ので、1 → 2 の順にしてください。

⚠️ ② は `production` から取るので、⚠️ **先に GitHub で v2.2.167 を production へマージ**しておくこと。
