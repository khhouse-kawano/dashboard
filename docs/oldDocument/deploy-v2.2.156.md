## ⚠️⚠️ 順序（⚠️ **入れ替えないこと**）

```
1. ① SQL（列追加）          ← ⚠️⚠️ 必ず最初
2. ① SQL（update_log）
3. ② VPS（Express の再ビルド）
4. ① フロント（build）
5. LPサーバー（3ファイル）    ← ⚠️⚠️ 必ず最後
```

### ⚠️ なぜこの順なのか

| | |
|---|---|
| ⚠️⚠️ **1 を飛ばして 3 を先に出すと** | ⚠️ ⚠️ **`Unknown column 'message'` で INSERT が落ちる。** ⚠️ **その間に届いた反響が丸ごと失われる**（⚠️ フォームには「送信に失敗しました」と出る） |
| ⚠️⚠️ **5 を先に出すと** | ⚠️ `message` を送っているのに ② が受け取れない。⚠️ ⚠️ **受付自体は成功する**（⚠️ 知らない項目は無視される）ので、⚠️⚠️ **誰も気づけないまま記入内容だけが捨てられる** |

⚠️ ⚠️ **1 → 5 の間はどの順でも壊れません。** ⚠️ 1と5の位置だけを守ってください。

⚠️ ⚠️ **1 だけ先に流しておく運用で構いません**（⚠️ 列が増えても既存の処理は何も変わらない）。

## 手順1　【① レンタルサーバー／phpMyAdmin】列を追加する

⚠️⚠️ **左サイドバーで対象DBを選んでから SQL タブを開くこと**（⚠️ `information_schema` のままだと #1109）。
⚠️ ⚠️ **PowerShell のパイプで流し込まないこと**（⚠️ 日本語が化けて #1064）。⚠️ **「インポート」を使う。**

⚠️ ファイル: `backend/scripts/sql/2026-10-01_ambassador_inquiry_message.sql`

```sql
ALTER TABLE `inquiry_ambassador`
  ADD COLUMN `message` TEXT DEFAULT NULL COMMENT 'ご質問やご要望（任意入力。顧客本人が記入）'
  AFTER `build_area`;
```

⚠️ 確認:

```sql
SHOW FULL COLUMNS FROM `inquiry_ambassador` LIKE 'message';
```

⚠️ ⚠️ **`Null` が `YES`、`Default` が `NULL` であること。**
⚠️⚠️ **`NOT NULL` になっていたら作り直すこと。** ⚠️ 未入力の反響が受け付けられなくなる。
