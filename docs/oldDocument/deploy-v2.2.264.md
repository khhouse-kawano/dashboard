## 順序
```
0. GitHub で v2.2.264 を production へマージ（PR）
1. ② VPS：git pull → 作り直し                    ← フロントより先
2. ① Dashboard のフロント（npm run build）
3. ① SQL：2026-11-11_update_log_2.2.264.sql      ← ⚠️ 1回だけ
```
- 1 より先に 2 を上げても壊れません（不動産企画係の売上が 0 と出るだけ）。

### 手順1　【② VPS】
```bash
cd ~/dashboard && git pull
dcp up -d --build express-api
dcp ps express-api
```
- `STATUS` が `Up` ならよいです（`Restarting` なら起動に失敗している。`dcp logs --tail 60 express-api` で理由を見る）。
- ⚠️ `dcp` は `--env-file .env.prod` を含む短縮コマンド。`docker compose -f docker-compose.prod.yml` だけで作り直すと DB_NAME などが空になり、② が起動しない（2026-11-11 に発生。この手順書の書き間違い）。

### 手順3　【① SQL】
phpMyAdmin で `2026-11-11_update_log_2.2.264.sql` を **1回だけ**流します。
```sql
SELECT no, version, date FROM update_log ORDER BY no DESC LIMIT 2;
```
一番上が 2.2.264 で、1行だけならよいです。

## 知っておくこと
- 数え方は変えていません。改修の前後で、3つの事業 × 6つの表示（今期・前の期・昨年実績・キャンセル非表示・併売店まとめ・入力の後）の全セル（92,007）が同じことを確かめています。意図して変えたのは次の2つだけです。
  - 中古住宅専門店の下の「不動産企画係」の店舗の行を出さない（不動産企画係の事業部として出す）。
  - **中古リノベの事業部の予算から、不動産企画係の予算を除いた**（今期はローカルで 24,500 → 13,100。除いた 11,400 は不動産企画係の事業部の予算に出る）。グループ予算は以前から両方とも入っていないので変わりません。
- デプロイ前に、画面の集計とは別の計算で数え直して突き合わせています（グループ・事業部・課・店舗の実績と予算、中古リノベ、不動産企画係。110項目すべて一致）。
- 予算は「1文字ごと」ではなく「欄を離れたとき」に保存します。入力したまま欄を離れずに画面を閉じると、その欄は保存されません。
- 「閲覧権限がありません」は、今選んでいる事業と、押した顧客の事業が違うときに出ます。全事業を見られる人でも、事業を切り替えてから開く必要があります。
