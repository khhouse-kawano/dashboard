## 順序
```
0. GitHub で v2.2.254 を production へマージ（PR）
1. ① フロント（v2.2.254 のブランチでビルドしたもの）
2. ① SQL：2026-11-06_update_log_2.2.254.sql   ← ⚠️ 1回だけ
```

### 手順1　【① フロント】いつもの手順
⚠️ v2.2.254 のブランチで `npm run build` をし直してから上げてください。

### 手順2　【① SQL】
phpMyAdmin で `2026-11-06_update_log_2.2.254.sql` を **1回だけ**流します（更新履歴と業務ガイドの記事）。
```sql
SELECT no, version, date FROM update_log ORDER BY no DESC LIMIT 2;
```
一番上が 2.2.254 で、1行だけならよいです。

## 終わったら（動作確認）
1. 不動産企画係の「チームサマリー」を開く
2. 見出しのすぐ下に「📊 売りKPI 媒体別（2026年6月〜2026年11月 累計）」「🏠 買いKPI 媒体別（…）」が出る
3. 売りKPI の期間を「2026年度…通期」にすると、合計の「売却反響」「通電」が、下の歩留まりファネルの「リード受信」「通電」と同じ数になる（買いも「反響受信」と同じ）
4. 集計の軸を「担当者別」「担当者×媒体」に変えると表が変わる。「⬇ CSV」でファイルが保存できる
5. 版の表示が ver2.2.254

## 注意
- 媒体の書き方が違うと別の行になります（例：「HOME's」と「HOME'S」）。以前のアプリと同じです。
- 選んだ見方（軸・期間・絞り込み）は保存しません。開き直すと媒体別・期首〜対象月の累計に戻ります（以前のアプリと同じ）。
