# デプロイ手順 v2.2.151

⚠️ 中身は ⚠️ **4件**。

| # | 何が変わるか | どこ |
|---|---|---|
| 1 | ⚠️⚠️ **イベント同期で「担当店舗」を選べるようになる**（⚠️ 空の予約も同期できる） | ⚠️ ① フロント ＋ ⚠️ ① PHP ＋ ⚠️ **② VPS** |
| 2 | ⚠️ **イベント同期の反響取得日が `reserved_at` になる**（⚠️ 従来は来場日時） | ⚠️ ① フロント |
| 3 | ⚠️ **「要確認」に担当営業の列が増える**（⚠️ 来場日未入力・本日の予定のみ） | ⚠️ ① PHP ＋ ⚠️ **② VPS** ＋ ⚠️ ① フロント |
| 4 | ⚠️⚠️ **PG HOUSE九州の資料請求メールを反響として取り込む** | ⚠️ ① PHP ＋ ⚠️ **GAS** |
| 5 | 更新履歴に1行増える | ① DB |

⚠️⚠️ **② VPS の再ビルドが必要。**
⚠️ ⚠️ **DB のテーブル定義は変えていません**（⚠️ **列の追加も無し**）。

---

## ⚠️⚠️ 順序

```
1. ② VPS（Express の再ビルド）    ← ⚠️ 先
2. ① PHP（3ファイル）
3. ① SQL（update_log）
4. ① フロント
5. GAS（PG HOUSE。⚠️ 任意のタイミングで可）
```

⚠️⚠️ **② を先に上げること。**
⚠️ ⚠️ **`list:event` と `daily_action` は ② が応答する。** ⚠️ ① だけ先に上げると、
⚠️ **② が古い形（店舗・担当営業なし）を返し、画面で選択肢が空になる。**

⚠️ ⚠️ **逆に ② を先に上げても ① は壊れない**（⚠️ 増えた列を使うのはフロントだけ）。

## 手順1　【② VPS で実行】Express の再ビルド

⚠️ ⚠️ **`git pull` は使わないこと。** ⚠️ **必ず分岐エラーになる。**

```bash
cd ~/dashboard
git fetch --depth 1 origin production
git checkout FETCH_HEAD
```
```bash
dcp build express-api
```
```bash
dcp up -d express-api
```

⚠️ 起動確認:

```bash
dcp logs --tail 50 express-api
```

⚠️⚠️ **次の2行が出ていること**（⚠️ **出ていなければ ① へフォールバックし続ける**）。

```
daily_action:list:        — 要確認の顧客（未同期・来場日未入力）と本日の予定
daily_action:list:order   — 要確認の顧客（未同期・来場日未入力）と本日の予定
```

⚠️ ⚠️ **`:order` が今回の追加分。** ⚠️ **これが無いと毎回 502 → ① 送りになる**（⚠️ 画面は動くので気づけない）。
