# 分析MCP 配布の手順（⚠️ **配布する人が読む**）

⚠️ 受け取る人が読むのは ⚠️ **[manual-setup-powershell.md](manual-setup-powershell.md)**。
⚠️ ⚠️ **こちらは渡す側の段取り**（⚠️ 鍵の発行と受け渡し）。

---

## ⚠️ 全体

```
1. ② VPS で APIキーを発行     ← ⚠️ 1人1本
2. キーを本人へ渡す            ← ⚠️⚠️ パスワード管理ツール経由
3. サーバーのzipを渡す          ← ⚠️ 配布済みなら不要
4. 本人が PowerShell で設定     ← manual-setup-powershell.md
5. こちらで疎通を確認
```

---

## ⚠️ 手順1　staff.id を調べる

⚠️⚠️ **キーは `staff.brand = 'Master'` の人にしか発行できない。**
⚠️ ⚠️ **それ以外に発行しようとすると CLI が止まる**（⚠️ 認証時に弾かれるだけなので先に止めている）。

⚠️ ① の phpMyAdmin で:

```sql
SELECT id, name, mail, brand FROM staff WHERE brand = 'Master' ORDER BY id;
```

⚠️⚠️ **渡す相手が Master でなければ、先に権限を上げるか、発行をやめる。**
⚠️ ⚠️ **権限を上げるかどうかは業務の判断。** ⚠️ 勝手に上げないこと。

---

## ⚠️ 手順2　② VPS でキーを発行する

```bash
cd ~/dashboard
```

```bash
docker compose -f docker-compose.prod.yml --env-file .env.prod exec express-api \
  node dist/cli/issueAnalysisKey.js --staff-id 12 --label "〇〇部長 ノートPC" --days 365
```

| 引数 | |
|---|---|
| `--staff-id` | ⚠️ 手順1で調べた `staff.id` |
| `--label` | ⚠️⚠️ **誰のどの端末か分かる名前。** ⚠️ 止めるときの目印になる |
| `--days` | ⚠️ 有効日数。⚠️ **省くと無期限**（⚠️ 365 を推奨） |

⚠️ 出力:

```
  所有者   : 〇〇 〇〇（staff.id = 12）
  用途     : 〇〇部長 ノートPC
  有効期限 : 2027-10-01 00:00:00

  APIキー  : khg_kpi_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

⚠️⚠️ **この表示は一度きり。** ⚠️ DBにはハッシュしか残らない。
⚠️ ⚠️ **控え忘れたら作り直すしかない**（⚠️ それが正しい挙動）。

⚠️⚠️ **1人1本。使い回さないこと。**
⚠️ ⚠️ **使い回すと「誰の操作か」が追えず、1人分だけ止めることもできなくなる。**

## ⚠️ 手順3　キーを渡す

⚠️⚠️ **チャット・メールに貼らないこと。** ⚠️ **パスワード管理ツール経由で本人へ。**

⚠️ 併せて伝えること:

- ⚠️ **あなた専用。他の人に渡さない**
- ⚠️ **紛失したら連絡する**（⚠️ **再確認はできない。作り直しになる**）

## ⚠️ 手順4　サーバーのzipを渡す

⚠️⚠️ **2026-10-01 時点で `tsconfig.zip` を配布済み。**

⚠️ 中身:

```
dist/                ← 本体
node_modules/        ← ⚠️ 入っている（npm install が要らない）
package.json
package-lock.json
tsconfig.json
```

⚠️⚠️ **展開しても入れ物のフォルダは作られない。**
⚠️ ⚠️ **`tsconfig\dist\index.js` のような形になる**（⚠️ `tsconfig\khg-analysis-mcp\dist\...` ではない）。
⚠️ 手順書の `$src` にはこの ⚠️ **`dist` と `node_modules` が並んでいるフォルダ**を入れてもらう。

### ⚠️⚠️ zip に入っていないもの（⚠️ **注意**）

| 入っていない | 影響 |
|---|---|
| ⚠️⚠️ **`scripts/`** | ⚠️ ⚠️ **`セットアップ.cmd` も `確認.ps1` も無い** |

⚠️ ⚠️ **自動セットアップは使えない。** ⚠️ 手で進める手順書のほうを案内する。
⚠️ ⚠️ **`manual-setup-powershell.md` の最後にある `確認.ps1` も動かない。**
⚠️ 必要になったら ⚠️ **`mcp-server/scripts/` を別途そのまま送る**（⚠️ 数十KB）。

⚠️ ⚠️ **なお `セットアップ.cmd` は 2026-09-22 に別PCで動かなかった経緯があり、
⚠️ どちらにせよ手順書のほうを使う方針である。**

## ⚠️ 手順5　本人に設定してもらう

⚠️ 渡すもの: ⚠️ **[manual-setup-powershell.md](manual-setup-powershell.md)**

⚠️ ⚠️ **要点だけ先に伝えておくと問い合わせが減る。**

| | |
|---|---|
| ⚠️ Node.js 20 以上 | ⚠️ 無ければ https://nodejs.org/ の LTS |
| ⚠️⚠️ **1行ずつ貼る** | ⚠️ まとめて貼ると想定外の動きをする |
| ⚠️⚠️ **窓を閉じない** | ⚠️ `$dir` などが消える |
| ⚠️⚠️ **Store版のClaude Desktopは設定ファイルの場所が違う** | ⚠️ ⚠️ **手順書どおりに `$cfg` を出せば自動で切り替わる** |

⚠️ 設置先は ⚠️ **`%LOCALAPPDATA%\khg-analysis-mcp`**（⚠️ 管理者権限は要らない）。

## ⚠️ 手順6　疎通を確認する

⚠️ 本人の画面で:

> 分析APIで使える集計軸と指標を教えて

⚠️ 一覧が返れば完了。

⚠️ ⚠️ **本人の手元で詰まったら、手順書の `手順7`（curl で 200 が返るか）を先に見てもらう。**

| 出た数字 | 意味 |
|---|---|
| ⚠️ **200** | ⚠️ キーもネットワークも正常。⚠️ **以降は Claude Desktop 側の問題** |
| ⚠️ 401 | ⚠️⚠️ **キーが違う／失効**（⚠️ こちらで作り直す） |
| ⚠️ 000 | ⚠️⚠️ **社内ネットワークから出られていない**（⚠️ ネットワーク側の話） |

## ⚠️ 止めるとき（⚠️ 退職・端末の紛失）

⚠️⚠️ **キーの値は分からなくても止められる。** ⚠️ `label` で引く。

```sql
SELECT id, staff_id, label, key_prefix, expires_at, revoked_at
  FROM analysis_api_key ORDER BY id DESC;
```

```sql
UPDATE analysis_api_key SET revoked_at = NOW() WHERE id = <止めるid>;
```

⚠️ ⚠️ **行は消さない。** ⚠️ **いつ誰に出したかの記録が消える。**

⚠️ 止めた直後から 401 になる（⚠️ **キャッシュしていない**）。
